## 1. Проект и подтверждённый production

Eldoria — Android-first/Windows 3D survival + строительство королевства, общий постоянный мир и кооператив; далее планируются NPC, экспедиции, PvP, дипломатия, разрушаемый ландшафт. Концепция — [ELDORIA_DESIGN_AND_ARCHITECTURE_v0.1.md](ELDORIA_DESIGN_AND_ARCHITECTURE_v0.1.md); **не выдавать планы за реализованные механики**.

## 2. Что действительно работает

- Godot Android и Windows клиенты, публичный WSS для общего постоянного мира, движения и переподключения; выбор KayKit героя, камера, джойстик, мобильный HUD, меню, инструменты внизу и количество дерева/камней/трав наверху.
- Процедурный лес, горы, дорога и вода с Quaternius моделями. Настройки Android Low/High и анимации. Дерево, камни, растения собираются сервером, исчезают/истощаются и сохраняются. Видимый в руке топор крафтится у костра, удваивает сбор древесины при экипировке; другие игроки видят его.
- Костёр, палатка и предпросмотр строительства; состояние построек и персональные инвентари сохраняются в PostgreSQL; мир общий. У волка есть HP, у игрока 100 HP, ближняя атака, смерть и возрождение.
- **TASK-039 в v0.5.10:** день подготовки **90 с**, ночь максимум **140 с**, четыре волка **последовательно** (следующий через 2,7 с), передышка **8 с**, общий таймер/счёт, ночное освещение. Каждый выживший после победы получает **+2 травы и +2 камня** после серверного сохранения. У костра можно **лечиться на 35 HP за 2 травы**, с проверкой расстояния ≤4 м и cooldown 3 с. Поздние подключения получают текущую фазу. Состояние записываемого инвентаря откатывается при сбое сохранения. Подробности: [TASK-039_CAMP_RAID_COOP.md](TASK-039_CAMP_RAID_COOP.md). [Реальный ночной кадр Godot](ui/TASK-039-night-defense.png), **не скриншот с Android**.

**Пока не реализовано:** одновременная группа волков, их урон по стенам/зданиям, ремонт, полноценный лук и меч, голод/еда, NPC, экономика, PvP, новые сложные биомы, разрушаемый грунт и королевства. **Раунд и HP волка не сохраняются** после рестарта Godot; инвентари/здания/сбор ресурсов — сохраняются. В качестве цели нападения используется первый найденный костёр; нескольких лагерей с независимыми атаками пока нет. Это **начальная кооперативная PvE активность**, не полноценная RPG на час.

## 4. Автоматический релиз и восстановление

**Не использовать GitHub Actions.** После локальной регрессии, фиксации GitHub ветки и проверки tree SHA на сервере выполнить:

```bash
sudo eldoria-release <next-version> release/<branch> --build-only
sudo eldoria-release <next-version> release/<branch> --deploy
```

`--deploy` собирает APK/ZIP, проверяет совпадение Android сертификата, делает PostgreSQL custom-format pg_dump, публикует и переключает Godot, затем проверяет HTTPS версию и SHA APK. Старые APK/ZIP остаются. Скрипт **не мигрирует SQL**.

**Важно!** В процессе v0.5.10 исправили две ошибки release script:
1. `v0510-release.conf` сортировался раньше `v059-release.conf`, systemd оставлял старую команду; сработал автооткат. Теперь постоянное имя **`zz-eldoria-release.conf`**, rollback восстанавливает предыдущий drop-in.
2. `pg_restore -l | grep -q` под `pipefail` давал ложный SIGPIPE **141** на валидном дампе. Теперь `pg_restore -l > world.pg.list` и отдельный `grep`; проверка порта `:7788` также исправлена.

**Третий deploy v0.5.10 — SUCCESS**, deployed source commit `37b2c3ea...`. Документы: [ELDORIA_RELEASE_AUTOMATION.md](ELDORIA_RELEASE_AUTOMATION.md), [RELEASE_0510_COOP.md](RELEASE_0510_COOP.md). **Не восстанавливать старый дамп PostgreSQL поверх прогресса, накопленного после выпуска.**

При публикации через Local Coder прямой `git push` может не работать из-за отсутствия HTTPS учётных данных; в предыдущем цикле использовался **GitHub connector** (tree/commit/update_ref). Проверять совпадение хеша дерева до деплоя.

## 5. Следующее действие

**Цель пользователя:** за короткие игровые итерации получить интересную игру **для двоих на 30–60 минут**. Приоритет — не сложные NPC, а ситуация, требующая совместной стратегии.

1. Проверить свежую телеметрию v0.5.10 на двух Android после реальной игры; нет ли критичных FPS/сетевых ошибок. Без замеров не заключать, что FPS исправлен.
2. Следующий игровой инкремент: **2–3 независимых волка одновременно**, server-owned ID/HP/агро, репликация обоим, late join, без дорогих вызовов каждый кадр; отдельный E2E с двумя игроками.
3. Затем **объект лагеря с HP**, волки атакуют его; простые баррикада/ремонт за ресурсы; чёткая победа/поражение. После — еда/голод, короткие задания и прогрессия. Не расширять ландшафт до замеров Android Low.
