## 1. Где сейчас проект

**Production:** Eldoria **v0.5.2**, https://bacus.dev/projects/eldoria/, Android ARM64 APK и Windows x64 ZIP. Клиент и выделенный Godot server используют WSS `wss://bacus.dev/eldoria/ws`. Версия — в `latest.json` и `server.json` сайта. Последний релиз в [TASK-019](TASK-019_TELEMETRY_RELEASE.md), игра уже имеет общий онлайн-мир, сбор/исчезновение деревьев и травы, три анимированных персонажа, костёр/палатку, анонимное сохранение в PostgreSQL, звуки, мобильный джойстик, предпросмотр строительства и телеметрию.

**Backend фактически:** Godot 4.5.2 **авторитетный real-time сервер**, .NET 10 **только приватный API для PostgreSQL и диагностики**, PostgreSQL 16 в собственной БД. Не начинать «писать сервер с нуля» по устаревшим TASK-001/013: это уже реализовано в ограниченном MVP.

**Отдельная разработка сейчас:** ветка `feature/TASK-020-stone-axe-crafting`, код топора в рабочем дереве, без production-изменений. Не публиковать этот код/не выполнять `003_stone_axe.sql` в production до явного разрешения.

**Исходники:** https://github.com/niko009/eldoria-game; сайт https://github.com/niko009/bacus.dev. Последний релиз исходников: commit `ceafb87dfb99f62f35a2536ff54b61063afdbcde`, [PR #15](https://github.com/niko009/eldoria-game/pull/15), основан на TASK-018. Исторические PR могут быть stacked/draft и ещё не слиты в `main`: **не начинать новые изменения просто от устаревшего main**.

## 3. Проверенные факты

- **Опубликована v0.5.2:** два независимых публичных WSS клиента прошли movement/Wave/reconnect; клиент реально отправил **синтетическую** запись диагностики через WSS → Godot → приватный .NET → PostgreSQL, и сводка её вернула.
- Сохранение: анонимные профили (локальный токен, в БД SHA-256), wood/stone/herb, выбранный герой, оставшиеся ресурсы, костёр и палатка. Перезапуск Godot не обнуляет мир.
- Показатели v0.5.2: средний FPS, худшие 5% FPS, p95 кадра, память, RTT, платформа/качество/версия. Опция ON/OFF; хранение 14 дней. **Нет достоверных аппаратных замеров FPS из одной синтетической записи**.
- Непосредственно во время актуализации документации запущены `client/tests/craft_axe_e2e.gd --initial` и `--restored` на тестовом **JSON**: PASS; `dotnet build` ранее прошёл. Реальный PostgreSQL E2E крафта **не считается подтверждённым до отдельного запуска**.
- На дату сверки публичные Godot/.NET-сервисы активны, PostgreSQL отвечает, `latest.json`/ `server.json` подтверждают v0.5.2. Состояние пользовательской сессии может измениться после проверки.

## 4. Что именно в разработке: TASK-020

`feature/TASK-020-stone-axe-crafting` отходит от релизного `ceafb87`. Реализовано в незакоммиченных изменениях: изготовление топора в пределах 4 м от костра; цена **2 wood + 2 stone**; одно изделие у игрока; 2 wood за рубку вместо одного; сервер проверяет стоимость/позицию; при ошибке сохранения стоимость откатывается; `axe` интегрируется в инвентарь и снапшоты JSON/PostgreSQL.

**Только тестовый вариант SQL:** `server/Eldoria.Persistence/sql/003_stone_axe.sql`, `ALTER TABLE eldoria_players ADD COLUMN axe ... DEFAULT 0`. Не применять к production и не включать в текущую конфигурацию live-сервера. `DEVELOPMENT_BUILD=true` в ветке, поэтому обычный игровой клиент не подключается автоматически к production.

Перед следующим релизом крафта: применить миграцию **к отдельной тестовой PostgreSQL**, прогнать `tests/run_postgres_e2e.sh` и полный `tests/run_dev_gameplay_e2e.sh`, проверить 2 клиента, Android touch, создание/повтор, эксплойты, откат по ошибке БД и совместимость существующих профилей; затем запросить разрешение на релиз.

## 5. Последовательность работы

1. Проверить `git status --short --branch`; **сохранить текущие незакоммиченные изменения TASK-020**, не делать `reset --hard` и не перебазировать без явного понимания состояния.
2. Сначала завершить/проверить TASK-020. Параллельно пользователь тестирует опубликованную **v0.5.2** и собирает реальную телеметрию. Для анализа использовать закрытый API `GET /v1/telemetry/summary` или read-only SQL по `eldoria_telemetry`, **не раскрывая ключи**.
3. Определить по p95 FPS и RTT, нужны ли оптимизации рендера или сервера; только затем добавлять другие большие механики (крафт, интерактивные здания, минимальные NPC).
4. После тестов — commit/PR и документация. Никакого живого релиза, миграций, обновления APK/ZIP без разрешения пользователя.

## 6. Ключевые ограничения

- Текущий мир ограничен и использует упрощённые цилиндрические/круговые коллизии; полное разрушаемое воксельное поле и подземные тоннели **не реализованы**.
- Сервер проверяет действия, но хранение полного снимка при изменении не рассчитано на MMO-масштаб. 10 игроков — целевой ориентир, а не подтверждённый нагрузочный предел.
- Нет NPC, боёв, королевств, дипломатии, survival-голода/холода, экономики и собственных городов.
- Анонимный секрет без восстановления при удалении данных приложения и без развитого контроля доступа.
- Телеметрию интерпретировать по платформам и графическим пресетам после появления **реальных**, а не синтетических наблюдений.
