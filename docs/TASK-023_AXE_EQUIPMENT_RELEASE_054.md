# TASK-023 — экипировка каменного топора и релиз v0.5.4

**Код:** `feature/TASK-022-stone-axe-live-ui` (включая TASK-022 и новую TASK-023).  
**Выход в production:** выполнен 2 ноября 2026 г., с резервным копированием и production-проверками. См. [TASK-024](TASK-024_RELEASE_054.md). Ниже сохранён исходный план проверки и отката.

## Игровая механика

- Крафт каменного топора из 2 wood и 2 stone разрешён не дальше 4 метров от костра; один топор на игрока. Проверка и сохранение — на сервере.
- После крафта топор лежит в рюкзаке. Игрок выбирает **слот 4** (или топор в инвентаре), сервер сверяет наличие и подтверждает экипировку. Выбор древесины/камня/травы снимает топор.
- **2 wood за удар** выдаются только при подтверждённой сервером экипировке; без топора в руках — 1 wood за удар. Остаток ресурса ограничивает фактический сбор.
- Экипировка хранится только в памяти сессии; при переподключении сбрасывается — пользователь выбирает топор снова. Сам изготовленный топор сохраняется в PostgreSQL.
- Сервер отказывает в экипировке без собственного топора и не принимает от клиента доверенные суммы ресурсов. UI показывает состояние подтверждения и активный инструмент.
- Миграция `server/Eldoria.Persistence/sql/003_stone_axe.sql` добавляет `eldoria_players.axe` с `DEFAULT 0` и ограничением от 0 до 1. Ранее созданные профили совместимы; анонимные токены не меняются.
- Дополнительных аккаунтов/паролей или изменения сетевого адреса нет.

## Проверки и артефакты

- Godot headless import и UI smoke.
- Отдельный Godot с JSON сохранением: создание/рестарт/повторное чтение, отказ сервиса сохранения, откат расходов, last wood clamp.
- Два независимых WebSocket-клиента с сервером: инвентарь второго игрока изолирован, экипировка разрешена владельцу и отклоняется при отсутствии топора, без повторного крафта.
- `tests/run_dev_gameplay_e2e.sh`: полный локальный ENet/WebSocket/визуальный/строительный регрессионный прогон.
- `tests/run_postgres_e2e.sh`: только на изолированной PostgreSQL; тестовый набор сохраняет топор между рестартами, проверяет старые профили и fail-closed авторизацию.
- Signed Android ARM64 debug APK, `versionName=0.5.4`, `versionCode=15`; Windows x64 ZIP.
- Публичный WSS smoke и SHA256 файлов проводить **после** развёртывания, не объявлять PASS заранее.

## Откат и риски

- До обновления сделать `pg_dump -Fc` production-БД, сохранить прежний API бинарник, WSS systemd override, `index.html`, `server.json`, `latest.json`. Сохранить файлы v0.5.3 на сайте.
- Выполнить только аддитивную миграцию; API v0.5.4 должен быть поднят **до** переключения Godot. На случай rollback API v0.5.3 будет игнорировать новую колонку, поэтому откат БД не требуется. Не удалять столбец — это уничтожило бы прогресс.
- Затем переключить Godot, манифест и файлы сайта на v0.5.4, проверить подключение двух клиентов и скачивание APK/ZIP с HTTPS; при сбое восстановить API + WSS override + публичные метаданные и перезапустить сервисы.
- Не заявлять о тестировании на физическом Android: только пользователь проверит удобство экипировки и новый игровой интерфейс после установки.
