# Eldoria — правила проверки задач

Тестировать по изменённым подсистемам; обязательный набор определяется риском задачи, а не формальной длительностью теста.

## Уровни проверок
| Когда | Минимальные проверки |
|---|---|
| Любой код | `git diff --check`, проверка синтаксиса/сборки и затронутые тесты; зафиксировать exit code |
| Геймплей, крафт, бой, ресурсы | Конкретные GDScript/E2E-тесты из `client/tests` и `tests/`; для связанных систем — `bash tests/run_dev_gameplay_e2e.sh` |
| Мультиплеер/сервер/сохранения | Соответствующие `tests/run_*network*_e2e.sh`, WebSocket/ENet, два клиента, авторитетность сервера и повторное подключение/восстановление по необходимости |
| Графика, камера, UI, VFX, анимация | Реально запустить игру, получить скриншот, проверить наличие объектов и перекрытие UI; при возможности проверить разные разрешения |
| Android/touch/производительность | Android-ориентированные E2E, затем ручная проверка на устройстве перед заявлением о готовности Android |

`tests/run_dev_gameplay_e2e.sh` — существующий комплексный набор; может требовать локального Godot и сервисов. Не делать вид, что он был запущен, если проверялись только отдельные команды. Не использовать скриншот как доказательство прохождения логических тестов.

## Визуальная проверка через MCP
1. Проверить `docs/GODOT_MCP.md` и актуальность копии проекта.
2. Запустить Godot и проверить `godot_health_check`, затем `godot_inspection_get_active_scene`.
3. Выполнить запуск (или сообщить, почему он невозможен); получить PNG фактического кадра, просмотреть его, проверить целевое изменение и очевидные регрессии.
4. При визуальном дефекте исправить **исходную рабочую задачу**, повторить тест и сравнить изображения. Не коммитить кэши Godot или временные MCP-скриншоты.
5. При отсутствии реальной графической сессии считать визуальную проверку **не выполненной**, даже если headless-запуск успешен.

## Отчёт по задаче
Указывать отдельно:
- Изменено: конкретные файлы/механики, ветка/коммит.
- Тесты: команды, результаты, exit code, известные ошибки.
- Визуально: полученный кадр и наблюдения либо «не проверено».
- Android/Windows/мультиплеер: что действительно проверено, что осталось.
- Релиз: «не выполнялся» до отдельной команды пользователя.

Не объявлять PASS по прошлым логам, тестовой копии другой ревизии или успешно пройденному импорту ассетов.
