## Сделанная оптимизация

1. `client/forest_world.gd`: препятствия (стволы/камни) индексируются по **неизменяемым** ячейкам 12×12 метров при процедурном построении мира. Queries `collides_at`, `_sweep_hits`, `camera_safe_target` перебирают только пересекающиеся ячейки с учётом максимального радиуса препятствия. Индексы сортируются в прежнем порядке, чтобы сохранить старую логику «первого столкновения». `obstacle_active` по-прежнему проверяется при каждом запросе: срубленные деревья не препятствуют проходу.
2. `client/main.gd`: только **визуальные** подсказки «рядом костёр / ресурс» и устаревшая скрытая текстовая строка обновляются не чаще одного раза в 200 мс, а не каждый кадр. Кнопка сбора/крафта и серверная проверка расстояний остались синхронными. Телеметрия продолжает собираться на каждом кадре.
3. Игровая геометрия, RNG, IDs ресурсов, коллизии, действия, сети, PostgreSQL и приватный .NET API **не изменены**. Не изменены шейдеры и плотность мира, чтобы не портить утверждённый visual style.

## Дальнейшая работа

**TASK-038 — Android performance validation → visual lock:** проверить v0.5.9 на обоих телефонах, минимум по 3 минуты: лагерь, густой лес и озеро; зафиксировать FPS и 5%-low на Low, качество изображения и нагрев, сравнить с v0.5.8. Если FPS не улучшился — использовать локальный diagnostic overlay (Настройки → Диагностика FPS) и исследовать CPU/physics vs draw calls; при подтверждённом GPU bottleneck — отдельно оптимизировать 3D/материалы, а не менять игровой сервер.

**Не добавлять тяжёлые новые эффекты в Low до фактических Android-замеров**. После стабилизации — следующий игровой этап: еда/голод, ночь и защита лагеря.
