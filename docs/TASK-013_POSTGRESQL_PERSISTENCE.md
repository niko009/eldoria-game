# TASK-013 — PostgreSQL вместо JSON, без логинов и паролей

**Статус:** локальная разработка в ветке TASK-013. **Не выпускать и не деплоить** без разрешения пользователя. Публичные сайт, Android APK, Windows ZIP и сервер остаются на **Eldoria v0.4.1**.

## Архитектура

```text
Android / Windows Godot
  → игровой сервер Godot (ENet LAN или WebSocket)
     → PostgreSQL World Store (GDScript, только server-side)
        → HTTP loopback 127.0.0.1:19091 + X-Eldoria-Server-Key
           → ASP.NET Core 10 Persistence API + Npgsql 10
              → PostgreSQL 16, выделенная БД Eldoria
```

- **Ни Android, ни Windows не получают PostgreSQL credentials**; к СУБД обращается только внутренний .NET API.
- `client/postgres_world_store.gd` предоставляет тот же интерфейс `configure`/`load_snapshot`/`save_snapshot`, который использовал старый JSON store. В `main.gd` PostgreSQL выбирается при `ELDORIA_PG_API_URL`; прежнее `ELDORIA_SAVE_PATH` оставлено только как временный legacy/offline режим, **взаимоисключающий** PostgreSQL.
- По умолчанию, без обеих переменных, сохранение выключено для изолированных E2E. **Ни один live сервис автоматически не перенастроен.**

## Упрощённая идентификация

Никаких логинов, e-mail и паролей. При первом запуске приложение создаёт случайный 256-битный идентификатор с помощью Godot Crypto и хранит в `user://eldoria-profile.cfg`. При входе он передаётся *только игровому серверу*; тот хранит в PostgreSQL **только SHA-256 токена**, выбранный аватар и приватный инвентарь. Одновременный вход с тем же идентификатором отклоняется. После переподключения или рестарта сервера восстанавливается профиль.

**Ограничения:** токен работает как пароль-доступ, хотя пользователь его не вводит. После удаления данных приложения доступ к старому персонажу теряется. Украденный токен позволяет выдать себя за игрока; нужен защищённый транспорт (WSS) при будущем публичном запуске, средства восстановления профиля и защита от злоупотреблений.

## Схема SQL (отдельная БД)

`server/Eldoria.Persistence/sql/001_init.sql`:

| Таблица | Ключ | Хранит |
| --- | --- | --- |
| `eldoria_worlds` | `world_seed` | Номер версии состояния (`revision`) и отметку последнего изменения |
| `eldoria_players` | `(world_seed, identity_hash)` | Выбранный герой (0–2), wood/stone/herb; контроль диапазонов CHECK |
| `eldoria_resources` | `(world_seed, resource_id)` | Количество ресурса, оставшееся в мире |

Сохранение одного состояния мира: **транзакция PostgreSQL**, row-lock мира, проверка `expected_revision`, одновременная запись ресурсов и инвентаря, увеличение `revision`; несовпадающая версия → **HTTP 409**, изменений нет. Это защищает от двух параллельных писателей с устаревшим состоянием. Данные не отдаются внешним клиентам.

**Ограничение MVP:** пока Godot пишет снимок всего небольшого мира после сбора/смены персонажа, API синхронно обрабатывается на localhost; это дороже, чем SQL delta/UPSERT. Для сотен игроков нужны более гранулярные транзакции и асинхронная обработка событий, а также резервное копирование и мониторинг БД.

## Запуск только в локальной разработке

**Выделенная тестовая PostgreSQL 16**, не используйте существующую production БД другого проекта. Настроить конфиденциальные переменные окружения *вне Git*:

```bash
# В отдельной тестовой БД предварительно выполнить sql/001_init.sql
export ELDORIA_POSTGRES_CONNECTION='Host=...;Database=eldoria_dev;Username=...;Password=...'
export ELDORIA_INTERNAL_KEY='<случайный длинный серверный секрет, минимум 24 символа>'
export ASPNETCORE_URLS='http://127.0.0.1:19091'
dotnet run --project server/Eldoria.Persistence/Eldoria.Persistence.csproj --configuration Release

# В ДРУГОМ терминале — Godot, на той же машине, что и .NET API:
export ELDORIA_PG_API_URL='http://127.0.0.1:19091'
export ELDORIA_PG_API_KEY='<тот же секрет>'
Godot_v4.5.2-stable_linux.x86_64 --headless --path client -- --dedicated-server
```

API отказывается слушать внешние адреса, а все маршруты требуют внутренний ключ. `ELDORIA_DB_AUTO_MIGRATE=1` применяется **только в изолированных тестах**, в нормальном окружении миграции выполняются явно.
