# TASK-033 — стилизованный топор в руках анимированных персонажей

**Дата:** 3 ноября 2026. **Основа:** `feature/TASK-032-mobile-hud-lock`. **Ветка:** `feature/TASK-033-character-equipment`.
**Состояние:** клиентская визуальная итерация для просмотра. **НЕ выпускать релиз**; production остаётся v0.5.7.

## Сделано

1. `client/stone_axe_visual.gd` — оригинальный каменный топор: деревянная рукоять, обмотка, многогранная каменная головка с подчёркнутой кромкой. Геометрия Godot `MeshInstance3D` + `ArrayMesh`/SurfaceTool, лёгкие обычные `StandardMaterial3D`. Нет текстур/шейдеров/тяжёлых частиц, скелета для самого оружия и коллизии.
2. `client/animated_actor.gd` — оружие прикреплено к встроенному `Rig/Skeleton3D/handslot_r` (`BoneAttachment3D`) **у каждого из трёх KayKit CC0 героев**, поэтому повторяет анимации ходьбы, бега и рубящего удара. Исправлена реальная ось руки; удалены показывавшиеся по умолчанию мечи Knight, в том числе `1H_Sword` и `2H_Sword`. Без топора герой пусторукий, топор появляется только после подтверждения экипировки. При смене класса/аватара оружие сохраняет визуальное состояние и крепится к новой руке.
3. `client/main.gd` — сервер остаётся единственным источником состояния `equipped_axes` (как раньше). После проверенной экипировки визуал меняется у владельца и отправляется всем остальным через `axe_visual_snapshot(id, equipped)`. Новому клиенту при входе отправляется состояние уже экипированных игроков после их `spawn_remote`. Это **новый визуальный RPC**, не меняет стоимость крафта, урон, добычу или DB schema. Самостоятельно клиент не может объявить топор серверу без владения.
4. На dedicated сервере 3D-модели оружия не создаются; сервер хранит только логический флаг.

## Ограничения и следующий визуальный шаг

- Топор — временная оригинальная стилизация для единого low-poly стиля, не сторонний лицензированный ассет.
- Меч, кирка, молот, лук пока не реализованы — они останутся недоступными в hotbar. Система крепления готова для будущих типов.
- Это только внешний вид оружия, а не переработка server gameplay. Новый RPC означает, что **когда-нибудь будущий релиз должен одновременно обновить клиент и игровой Godot сервер**.
- Следующая визуальная задача — более законченные **модели палатки, костра и построек**, а также визуальный отклик на рубку/сбор ресурсов; затем арт-стайл lock перед насыщением механиками.
