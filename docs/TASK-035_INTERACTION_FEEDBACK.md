# TASK-035 — visual response to harvesting and character actions

**Дата:** 3 ноября 2026. **Ветка:** `feature/TASK-035-interaction-feedback`. Основа: TASK-032 + TASK-033 + TASK-034. **Целевой релиз:** v0.5.8, Android+Windows+dedicated Godot.

## Что изменилось
1. **Удары и движения:** у всех трёх KayKit героев сбор дерева без топора использует `PickUp`, с действительно экипированным топором — `1H_Melee_Attack_Chop`. Сбор камня/травы остаётся `PickUp` (пока кирка не реализована). Так персонаж больше не рубит воздух «невидимым топором».
2. **Направление действия:** когда сервер подтвердил сбор ресурса, персонаж разворачивается **визуально к реальному расположению дерева/камня/травы**, потом проигрывает действие. Координаты, серверная физика и скорость игрока не меняются.
3. **Визуальная награда:** над настоящей точкой добычи появляется маленький плавающий `Label3D` (WOOD/STONE/HERBS), двигается вверх и исчезает за ~0,8 секунды. Маркер виден всем клиентам, получившим подтверждённое `gather_effect`, но не создаётся при отказе сервера.
4. **Контроль расходов:** максимум пять таких Label3D одновременно, максимум пять burst-эффектов (как раньше), полная очистка при disconnect/clear и после таймеров. На dedicated headless сервере ничего не рендерится. В результате используется уже существующий RPC без изменения схемы.
5. **Без фиктивных цифр:** в существующем RPC `amount` обозначает **оставшиеся ресурсы в дереве/камне**, не количество добытого. Поэтому маркер честно показывает только тип, а ресурсы с реальным количеством отображаются в HUD.

## Что не изменено
Схема PostgreSQL, .NET persistence API, ID ресурсов, логика крафта, ресурсы и стоимость построек, PvE/урон, авторизация и сохранение мира. Server-side authoritative подтверждение остаётся обязательным. Новые визуальные состояния TASK-033 (топор у остальных игроков) требуют одновременно нового dedicated и новых клиентов; релизный скрипт переключает их вместе.
