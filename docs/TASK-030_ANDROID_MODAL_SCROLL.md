# TASK-030 — Android: прокрутка меню и защита от случайных нажатий

**Исправление на базе production v0.5.6.** Цель выпуска: v0.5.7. В Android landscape-панелях «Настройки», «Рюкзак», «Строительство» и «Крафт» список не прокручивался обычным свайпом.

## Причина и воспроизведение

Реальный `ScrollContainer` в Godot 4.5.2 содержал `Button` с `mouse_filter=STOP`. При `InputEventScreenTouch` + `InputEventScreenDrag`, начатом на кнопке, прокрутка не выполнялась. Реальный тест (экран 800×360) на предыдущем production-коде: `settings child_min=440, viewport=204, scroll_vertical=0` после свайпа 220 px → FAIL.

Первый вариант явного touch pan позволял прокручивать, но выявил вторую ошибку: синтезированное Godot mouse-up событие **активировало кнопку под пальцем** (например, `quality` → смена качества при свайпе). Поэтому исправление включает защиту от кликов.

## Реализация

- `client/ui/touch_scroll.gd`: единый `EldoriaTouchScroller` для рабочего UI и UI Preview.
- При касании внутри видимой области `ScrollContainer` отслеживает **только указанный finger index**. При `ScreenDrag` с накопленным перемещением более 8 px управляет `scroll_vertical`; жест продолжается даже если палец вышел за пределы видимой области. Другие пальцы и касания вне области не влияют на список.
- На время свайпа блокируются **только сигналы кнопок внутри прокручиваемого содержимого**. После отпускания пальца блокировка снимается с небольшой задержкой (100 мс), чтобы Android mouse-emulation release не запускал случайный `pressed`. Обычный короткий тап без свайпа остаётся рабочим.
- Сброс tracking и top scroll при открытии/закрытии/смене панели. Вкладки и кнопка закрытия, джойстик, hotbar, жесты камеры и свайпы вне открытой панели не перехватываются.
- В `ScrollContainer` остаётся обычная прокрутка мыши/колёсиком для Windows. Доступные материалы, крафт, серверные RPC и PostgreSQL не изменены.

## Автотест

`client/tests/android_modal_scroll_e2e.gd` — тест на Godot 4.5.2, landscape 800×360, настоящие `InputEventScreenTouch` и `InputEventScreenDrag` через `Input.parse_input_event`, касания поверх кнопок:

1. Вкладки settings/inventory/build/craft прокручиваются в обе стороны, если контент больше viewport.
2. Во время свайпа по «Графика: переключить» не выполняется действие.
3. В инвентаре свайп по ресурсу не снимает экипированный топор.
4. После закрытия панели свайп не двигает контент.
5. После свайпа нормальный короткий тап всё ещё активирует кнопку настройки.
6. UI Preview тоже прокручивается.
7. Этот тест добавлен в общий `tests/run_dev_gameplay_e2e.sh`, чтобы проблема не вернулась.

## Проверки и ограничения

- Старый код v0.5.6: отдельный тест с правильной калибровкой ввода → **FAIL**, `settings scroll_vertical=0`.
- Новый код: тот же тест → **PASS** для всех панелей и Preview.
- Полный локальный игровой E2E — результат указывается по факту прогона.
- Визуальный тест на физическом Android и фактический отзыв после установки APK v0.5.7 **ещё нужны**. Автоматизированная симуляция touch-жестов на Godot Linux не заменяет физический телефон.
