# Eldoria TASK-049 — навыки, манекены, совместимое сохранение

**Ветка разработки:** `feature/TASK-040-multi-wolf-coop` от `release/eldoria-v0.5.10`.
**Кандидат:** v0.5.11. Не считать опубликованным без `ELDORIA_RELEASE_SUCCESS` и публичных проверок.

## Возможности

- Три отдельных навыка: `archery`, `spear`, `defense`, опыт 0–1 000 000 на профиль.
- Уровень для интерфейса: `1 + floor(sqrt(xp / 25))`. Пока **без бонуса к боевой силе**. На HUD показаны уровни `Л`, `К`, `Щ`, подробный XP в tooltip.
- За подтверждённые сервером попадания луком/копьём по волкам и мирным животным — по 2 XP; за попадание по тренировочному манекену — 3 XP не чаще раза в 2 секунды на персонажа/манекен; за принятый удар со щитом — 1 XP.
- Два неподвижных тренировочных манекена у стартовой поляны: не атакуют, не уничтожаются, не засчитываются в рейд, не дают ресурсы и обычные тренировочные очки.
- Мирные животные и кооперативный бой из TASK-040…048 остаются в игре.

## Долговременность

- Существующие анонимные стабильные `identity_hash` и инвентарь сохраняются. Пароли не добавляются.
- Additive SQL migration: `server/Eldoria.Persistence/sql/004_skills_crafting.sql` добавляет 6 новых типов инвентаря и 3 поля XP с безопасными `DEFAULT 0` и ограничениями. Данные прошлой версии не удаляются.
- `.NET Persistence API` расширен в `Program.cs` с обратной совместимостью старого формата и валидацией XP; Godot `postgres_world_store.gd` и `world_save.gd` принимают старые профили и заполняют новые поля нулями.
- Каждое изменение XP подтверждается серверным сохранением; при отказе хранилища XP откатывается. Все параметры пользовательской атаки проверяются на сервере; клиент не передаёт сумму XP.
- Прототипные очки `practice_points` из TASK-048 по-прежнему сбрасываются при переподключении. Новые три XP-навыка сохраняются.

## Реальные проверки

- `bash tests/run_task049_skills_e2e.sh` — JSON-профиль + расширенный инвентарь + 3 навыка после нового запуска Godot.
- `client/tests/task048_passive_e2e.gd`, `tests/run_passive_network_e2e.sh` — 6 целей, тренировочные манекены, ограничение фарма, 2 игрока.
- `tests/validate_task049_pg_api.sh` — одноразовый контейнер postgres:16-alpine, миграция после старого профиля, HTTP GET/PUT нового API, защита от отрицательного XP; **продакшен-БД не используется**.
- `dotnet build`, `dotnet publish -r linux-x64 --self-contained`, полная регрессия `bash tests/run_dev_gameplay_e2e.sh`.

## Протокол развёртывания

1. Проверить релизный ref GitHub и текущую публичную версию (строго 0.5.10).
2. Изолированная PostgreSQL миграция и полный набор тестов. Собрать v0.5.11 через `eldoria-release ... --build-only`.
3. На production до миграции сделать *отдельный* `pg_dump -Fc` и резервную копию бинарника Persistence API. Накатить SQL 004 транзакционно. Установить новый протестированный API, проверить health/read/неизменность существующих данных.
4. `sudo eldoria-release 0.5.11 release/eldoria-v0.5.11 --deploy` — скрипт создаст ещё один бэкап, проверит Android signing cert и публичные SHA, обновит сайт и Godot service.
5. Внешняя проверка WSS с двумя клиентами, `server.json`, `latest.json`, APK и Windows ZIP.
6. При ошибке на шаге 4 — script rollback Godot и манифестов. **Нельзя восстанавливать старую базу автоматически**: это может уничтожить прогресс реальных игроков.

Известные ограничения: геймплейные бонусы от уровней не включены, продвинутые анимации/графика и тесты на физических Android ещё нужны.
