# TASK-071 — Компактная мастерская: плитки + карточка рецепта (P0, TODO)

**Проблема:** сейчас `client/ui/crafting_panel.gd` строит длинный набор широких RecipeCard, каждая содержит всё описание, состав и действия; поиск и повторный крафт неудобны. Требование пользователя: выбрать иконку → увидеть 1 рецепт и материалы → нажать «Создать».

**Дизайн:** две области внутри одного ScrollContainer/адаптивного контейнера:
- Слева/сверху: компактная сетка квадратных иконок (Android: 3–4 колонки, Windows: 5–6), название при выборе, категории «Оружие», «Броня», «Еда/зелья», «Боеприпасы». На каждой плитке маленький индикатор `готово` зелёным / `не хватает` красным / лимит серым.
- Справа/снизу: **одна** раскрытая карточка выбранного рецепта: крупная иконка, короткое назначение, ингредиенты с `имеется/нужно`, зелёные доступные и красные недостающие, `Создать ×1`, для стрел `×5` только при наличии ресурсов, опционально `Максимум` с серверным лимитом.
- После крафта выбранная плитка, категория и scroll-position остаются прежними; подсветка и числа обновляются. Никакой кнопки «Использовать» у крафта — она в HUD/инвентаре (TASK-070/072).
- Для предметов без костра сообщать отдельно: `Нужен костёр рядом`, а не скрыто отключать кнопку. Выбор плитки без ресурсов всегда доступен.

**AC:** 15+ рецептов помещаются в скроллируемую сетку, один рецепт читается без прокрутки на 640×360. Повторное изготовление стрел с одного места. На двух экранах UI не перекрывает кнопки; сохранено закрытие/тач-скролл. Сервер пересчитывает реальные ингредиенты и лимиты, UI не выдаёт предмет сам.

**Тесты:** новые Godot UI smoke; старые `task046_crafting_sort_badge_e2e`, `task053_crafted_weapons_ui_e2e`, `android_modal_scroll_e2e` адаптировать без ослабления ожиданий.
