# Eldoria — план улучшений после v0.5.21

**Сформировано:** 2026-11-04, 22:42 Europe/Chisinau.
**Желаемый контрольный рубеж:** 2026-11-05, вечер (ориентир 22:42 Europe/Chisinau).
**Статус:** требования зафиксированы, **не реализованы**. Этот документ не утверждает, что работа выполняется в фоне. Для выполнения нужны последовательные рабочие итерации с инструментами.

## Вывод
Сейчас нужно не наращивать механики бездумно, а замкнуть понятный игровой цикл: добыча → видимые награды → изготовление → экипировка → применение в бою → прогрессия → новые враги. Изменение боевого баланса обязательно проверять одновременно с новыми мобами и источниками восстановления здоровья/маны.

## Подтверждённое состояние v0.5.21

- **Маг:** 3 заклинания (fire/frost/storm), мана восстанавливается по 8/сек. Существующий визуальный MageStaff (`client/animated_actor.gd`) генерируется только при `avatar_choice == 2 && combat_item == "unarmed"`; магический посох нельзя изготовить/улучшить, урон заклинаний не связан с отдельным XP магии. Нужно проверить ориентацию, руку, видимость модели в реальной сборке Android.
- **Бой:** XP лука, копья и защиты есть; общий `practice_points` даётся за попадание по животным. Отдельного `magic_xp` нет; PvE урон волка = 12, альфы = 18, оружие/спеллы убивают относительно быстро. Волки целятся в ближайшего игрока и могут нападать группой.
- **Олени:** `client/passive_creatures.gd`: HP=55; реагируют на игрока ближе 7 м, убегают со скоростью 4 м/с, не контратакуют; кролики реагируют ближе 6 м, скорость 3 м/с. Возрождение через 20 сек.
- **Повязка:** мгновенно лечит 40 HP **в любом месте**, но доступ к кнопке использования спрятан в панели крафта; нельзя применить при полном HP. Ремкомплект восстанавливает 60 HP лагеря **только ночью**, возле костра, когда повреждён целевой лагерь. Это нужно объяснять игроку и делать контекстным действием.
- **Инвентарь:** отображает сетку предметов, но нет силуэта героя и независимых слотов. `equipped_combat` — один слот, поэтому щит нельзя сочетать с мечом/посохом; кожаная броня сейчас действует по факту нахождения в инвентаре, без экипировки.
- **Крафт:** вертикальный список карточек во всю ширину, на каждой ингредиенты и кнопки; повторный крафт уже не закрывает окно, но UX всё равно чрезмерно громоздкий.
- **Зум Android:** pinch реализован в `client/platform_input.gd` и покрыт `task055_targeting_zoom_e2e.gd` на синтетических событиях, но на реальном Android пользователь подтверждает неисправность. Не считать исправленным до проверки физических жестов, перекрытий HUD и двух разных экранов.
- **Добыча:** выдаётся в инвентарь после убийства, сообщение `_attack_feedback` уже есть, но нет заметного, отдельного уведомления «Добыча +...», очереди событий и понятного журнала.

## Сквозные инварианты и критерии выпуска

1. Клиент отправляет только действия и ID, не наносимый урон/XP/координаты наград; сервер валидирует расстояние, ману, рецепты, экипировку, время суток и хитбоксы.
2. XP не начисляется дважды при повторном RPC и по манекену бесконечно. Ограничить фарм исцелением себя на полном HP.
3. Независимые слоты главной/второй руки; двуручные предметы исключают щит; одноручный посох может сочетаться со щитом. Броня действует только будучи надетой.
4. Инвентарь и слоты переживают переподключение и перезапуск API/Godot, миграции аддитивные, backup до production, rollback бинарника без автоматического восстановления БД.
5. Две реальные игровые сессии (Windows+Android; Android+Android), моб выбирается, урон и добыча синхронизируются, TPS/FPS проверены на телефонах.
6. Headless unit/E2E + физический Android UX; успешный headless pinch не доказывает работу на телефоне.
7. Ни один релиз не считать законченным до публичного `latest.json`, HTTP 200 APK/ZIP, `ELDORIA_RELEASE_SUCCESS`, `systemd active`, загруженных профилей и чистых критичных логов.

## Ожидаемый фидбек на ближайшей проверке

- Маг видит посох в руке, выбирает улучшенный посох, видит XP и уровни магии, может пополнить ману.
- Нажатие на повязку в HUD лечит без костра; ремкомплект показывает, почему сейчас недоступен.
- В крафте сначала компактные иконки, затем панель одного рецепта; материалы зелёные/красные; повторное изготовление без прыжка списка.
- Олень не убегает мгновенно от подхода; нейтральный моб защищается только после удара, ночной меняет состояние по времени.
- После убийства на экране видно, какой предмет выпал и сколько XP начислено.
- Игра дольше удерживает в бою: не мгновенные смерти от пачки волков и не убийство любого моба за 1–2 удара.
