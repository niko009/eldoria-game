# TASK-026V — Visual Foundation + Performance Diagnostics (автономная задача Codex)

**Дата анализа:** 2026-11-02 (UTC). **Целевая ветка:** `feature/TASK-026V-visual-foundation`; база — проверенная `feature/TASK-025B-tool-hotbar` (commit `0d1bb14b62bd1b7e46190f5ea359daffadd812f4`).

## Цель

За одну автономную итерацию получить **визуально цельный, заметно более красивый и измеряемый playable slice** Eldoria: статическую демонстрацию настоящего 3D-мира у стартовой поляны/костра, в лесу и у озера, вместе с уже утверждённым mobile-first HUD. Создать инструменты измерения, чтобы затем проверить на двух Android реальную цену визуальных улучшений. Сюжет, новые механики, дневной цикл, PvP, NPC и multiplayer backend сейчас не развивать.

**Codex действует автономно и не задаёт вопросов.** Если необязательный входной материал, ассет или инструмент недоступен, выбирает описанный fallback, фиксирует ограничение и продолжает. Никаких просьб о сервере, учётных данных или сборках.

## Что показали реальные production-логи (read-only, не менять production)

На v0.5.4, 2 ноября 2026, сохранены анонимные агрегированные замеры (`eldoria_telemetry`):

| Платформа | Quality | Отчётов | avg FPS | avg 5%-low FPS | avg p95 кадра | avg RTT |
|---|---|---:|---:|---:|---:|---:|
| Windows | High | 54 | 54.3 | 50.3 | 21.1 мс | 101.9 мс |
| Android | Low | 15 | 31.0 | 19.3 | 60.9 мс | 120.6 мс |
| Android | High | 1 | 55.5 | 16.6 | 60.4 мс | 63.0 мс |

Android Low: 18:06–18:12 UTC отдельные минутные измерения 13.0–17.5 FPS; 19:09–19:15 UTC 34–80.9 FPS. Данные не содержат device ID, модели, карты/позиции, состояния питания, температуры или уровня заряда, поэтому **нельзя определить, какой из двух телефонов или какая игровая сцена породили конкретный отчёт**. Одного High-замера недостаточно для оценки качества.

У Windows все 54 записи имеют `memory_mb=1`. Это **не достоверное реальное использование памяти**, потому что `client/performance_telemetry.gd` использует `OS.get_static_memory_usage()`, документированный в Godot 4.5 только для debug-сборок, и принудительно ограничивает результат минимумом 1. Не использовать эту величину как основание для memory-оптимизации. Любые изменения удалённого формата telemetry или SQL — отдельная задача после согласования.

Сервисы `eldoria-ws-test` и `eldoria-persistence` на момент проверки активны, `NRestarts=0`, в журналах за 72 часа нет ошибок private API и OOM. Три серверные ошибки WebSocket `Missing or invalid header upgrade` датированы **2026-11-01 19:20–19:21 UTC** — это не свидетельство ошибок тестов Android/Windows 2026-11-02. По серверным логам нельзя подтвердить именно два уникальных Android-устройства.

## Архитектура, которую нельзя ломать

- **Godot 4.5.2**, `GL Compatibility` для Windows и Android; не переключать проект на Forward+, Vulkan или новый major Godot.
- Релиз в production **v0.5.4**; текущая branch включает **TASK-025** (первый бой) + **TASK-025B** (горячая панель инструментов). Codex правит только новую ветку и **не выпускает релиз**.
- `client/forest_world.gd` строит **детерминированные** биомы и массивы ресурсов; порядок генерации `resources` и их числовые ID критичен для существующей PostgreSQL. **Нельзя** менять seed, порядок RNG вызовов, создание/число resource nodes до окончания baseline ID-check. Добавлять декоративные элементы отдельным визуальным проходом, не затрагивая resource IDs и размещение коллизий.
- `client/graphics_profile.gd`: Android по умолчанию **LOW** (отключены тени солнца и опциональная foliage); Windows **HIGH**. Не делать Low дороже без измерения.
- Растительность собрана в `MultiMeshInstance3D`; не заменять её сотнями отдельных Node3D и не делать дорогостоящие прозрачные материалы на каждой травинке.
- Существующие `client/Main.tscn`, `client/main.gd`, `client/ui` с HUD, kрафтом и экипировкой должны работать без изменения сетевого RPC, `server/`, SQL, anonymous identity и мира.
- Авторизованный стиль пользователя: **D, mobile-first, clean fantasy RPG**. Нижний hotbar — **только векторные иконки инструментов без счётчиков**, сверху — ресурсы wood/stone/herb с числами; тёмное полупрозрачное rounded UI, аккуратные золотистые акценты, HUD не закрывает центр. Сохранить его без большого redesign.
- Сейчас в репозитории **НЕТ исходного утверждённого художественного PNG**: `docs/ui/TASK-021D-layout-reference.svg` — только композиционная схема, `docs/ui/TASK-025B-HUD-preview.png` — фактический Godot screenshot старого 2D Preview. **Не утверждать, что оно визуально совпадает с оригинальным концепт-артом**. Если пользователь прикрепит оригинал к задаче Codex — использовать его как художественный референс. Иначе следовать указанной здесь стилистике.

## Реализация в порядке приоритета

### 1. Диагностика (обязательна)

- Отдельный **локальный debug overlay**, включаемый F9 и из меню настроек: FPS (avg и 5% low), p95 кадра, physics/CPU time (если Godot monitor доступен), 3D objects/draw calls (если доступен monitor), выбранное качество, число видимых деревьев/деталей, разрешение/viewport и состояние сцены (camp/forest/lake). Числа от недоступных monitors показывать как «нет данных», а не 0 или выдуманные значения.
- При необходимости локальный текстовый/CSV отчёт в `user://`, только через явное включение debug, без device ID, IP, токена игрока, точных координат или сетевого экспорта. Данные остаются на устройстве, сбор выключен по умолчанию.
- Исправить **локальную интерпретацию памяти**: явно отметить недоступность `OS.get_static_memory_usage()` в release / не показывать `1 MB` как достоверный RSS. Не менять `POST /v1/telemetry` и таблицу без сервера.
- Добавить повторяемый `docs/TASK-026V_DEVICE_TEST_PLAN.md` для двух реальных Android: 3 сценария (полянка/лес/озеро), Low и High, 3–5 минут на сценарий после прогрева, фиксировать медиану/5%-low/p95 и субъективные фризы. Точное FPS High на Android не обещать.

### 2. Один художественный visual pass — **без новых игровых фишек**

- Актуальный мир, а не отдельный пустой mockup: улучшить **палитру земли, alpine skyline, мягкое небо, воздух/туман, атмосферу леса, берег и воду**, чтобы игра выглядела цельной stylized fantasy (цветной, чистой, не кислотной и не тёмной).
- Выделить **три обзорных ракурса**: (A) лагерь/старт, (B) густой лес, (C) водоём на фоне гор; согласованные освещение и композиция.
- В первую очередь менять **свет, материалы и палитру**, а не число полигонов и draw calls. Избегать дорогих screen-space эффектов на Android Low: SSAO, volumetric fog, много динамических огней, обилие прозрачных частиц и теней. Для High можно отдельные эффекты только при сохранении отключаемого Low fallback.
- Использовать существующие Quaternius CC0 ассеты, примитивы, материалы и Godot nodes. **Не скачивать платные/неподтверждённые ассеты, не добавлять лицензии с несовместимыми условиями**.
- Сделать привлекательный костёр и воду, но без дорогого mobile shader; если shader нужен, обеспечить совместимость GL Compatibility.
- **Не трогать RNG-порядок/позиции gameplay ресурсов**, коллизии и серверную симуляцию.

### 3. Визуальная проверка (обязательна)

- Из реальной игровой сцены/изолированного локального world preview сохранить минимум **6 PNG**: три ракурса × LOW/HIGH при одинаковой камере и освещении; хотя бы **1280×720** (при наличии Xvfb/GL), и отдельные UI-наслоения для landscape 800×360 либо максимально доступного меньшего окна.
- Код захвата, если нужен, оставить в `client/tests/` или `tools/` и документировать. Если реальный OpenGL недоступен, попытаться headless renderer smoke, отметить отсутствие скриншотов, **не блокировать коммит**.
- Сравнить «до / после» на одинаковом ракурсе. Не подменять реальный Godot screenshot картинкой от генератора.
- Проверить, что ни один обязательный collider/ресурс не стал невидимым на Low.

### 4. Проверка безопасности изменений (обязательна)

- `Godot 4.5.2 --headless --editor --quit`, `client/tests/live_ui_smoke.gd`, `client/ui_preview/preview_smoke.gd`, `tests/run_dev_gameplay_e2e.sh` если инструменты доступны; отдельно проверить детерминированность resource ID/мира, отсутствие регрессий в two-client WS, крафте, экипировке, бою.
- Если существующий тест не проходит из-за окружения — зафиксировать точный лог/причину, устранить кодовую проблему, не выдавать недоступный инструмент за PASS.
- Собрать таблицу `до / после` по **локальному** fps/frametime только если обе стороны запущены на **том же** рендерере и железе; программный Xvfb/llvmpipe не сравнивать с Android и не заявлять оптимизацию Android без реальных устройств.
- Дополнительно проверить материалы, туман, контраст, UI и сенсорные цели на двух landscape-размерах.

## Критерии сдачи

- Есть существенное визуальное улучшение **одного игрового фрагмента** без потери единого утверждённого HUD.
- Есть воспроизводимый диагностический режим и инструкция реального сравнения **на двух Android**.
- Нет изменений database/network/API, нет сброса мира и resource IDs, нет дорогих обязательных эффектов в LOW.
- Есть **`docs/TASK-026V_RESULT.md`**, реальные скриншоты (если технически доступны), список файлов, проверок и ограничений; минимальные тесты Godot PASS, причины других непрохождений задокументированы.
- **Только коммит(ы) и push** в `feature/TASK-026V-visual-foundation`. Не делать merge, PR, APK, Windows ZIP, релиз, деплой, изменения сервера. Не создавать фиктивную оценку Android FPS.
- Финальный ответ Codex: коротко, что изменил, ссылки на PNG, какие тесты реально прошли, что нельзя проверить без Android, commit SHA и GitHub branch.

## Отдельная задача, НЕ для Codex-026V

Production telemetry `memory_mb` сейчас некорректна на Windows и бесполезна для оценки реального RSS; возможный редизайн полей/валидатора .NET/SQL выполнить локально через Local Coder, с миграцией и релизом, после согласования. Сейчас не менять формат существующей DB/API.
